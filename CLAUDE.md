# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

**Local development (requires `uv`):**
```bash
uv sync                          # install all deps including dev extras
uv run ruff check .              # lint
uv run mypy --strict pipeline/   # type-check (strict; tests/ are excluded)
uv run pytest tests/ -v          # full test suite
make check                       # lint + typecheck + tests in one shot
```

**Run a single test:**
```bash
uv run pytest tests/test_phase2.py::test_name -v
```

**pacod-id's Python package** (`pacod_id`) is a vendored wheel: `scripts/vendor-pacod-id.sh [../pacod-id]` builds it from the checkout's committed HEAD into `vendor/wheels/`, records the commit in `vendor/PACOD_ID_VERSION`, and updates `uv.lock` (`[tool.uv.sources]` points at the file; it is in the `ui` and `dev` groups). It ships no `py.typed`, so mypy follows it via an override; `make audit` skips it (`--no-emit-package pacod-id`).

**Type-check scope:** `make typecheck` (part of `make check` and CI) runs `mypy --strict` on both `pipeline/` and `web/`. Other targets: `make coverage` (pytest-cov), `make audit` (pip-audit over the locked dependencies).

**Route contract:** `tests/test_route_contract.py` snapshots the ordered route table and OpenAPI schema of both apps (`tests/snapshots/`). An intentional API change requires regenerating them with `KB_UPDATE_ROUTE_SNAPSHOTS=1 uv run pytest tests/test_route_contract.py`.

**Retrieval eval** (`docs/retrieval-eval.md`). The v2 suite runs a multilingual corpus (`eval/corpus/`, rebuilt by `eval/corpus/build_corpus.py`) and 92 section-labelled queries (`eval/golden_v2.jsonl`) through the real ingest and search path:
```bash
make eval                      # BGE-M3 on CPU; index cached in eval/.cache/<key>; results in eval/results/
make eval EVAL_ARGS="--split dev --no-latency --keyword-mode or"            # one variant, quality only
make eval EVAL_ARGS="--compare eval/results/<baseline>.json"                # identical rankings + paired deltas
make eval EVAL_ARGS="--under-ingest"                                        # latency while an ingest runs
make eval EVAL_ARGS="--rerank BAAI/bge-reranker-v2-m3"                      # with a reranker
make rerank-probe; uv run python -m eval.embed_bench                        # reranker / embedding CPU cost
make eval-smoke                # legacy fixtures smoke (MockEmbedder; PYTHONHASHSEED=0)
```
It exits 1 when a corpus file does not ingest with status `ok` and its declared language, or when a golden label or its `must_contain` snippet no longer resolves. CI runs it with `--embedder mock` as an integrity check.

## Architecture

Operator and reader docs: `docs/runbook.md` (running it), `docs/architecture.md` (how the parts fit), `docs/metadata-contract.md` (what RAG consumers get), `MIGRATIONS.md` (upgrades). The notes below are for working on the code.

### Two-container design

```
Browser ── sign-in pages, authorize, logout ──▶ pacod-id public listener (KB_ID_ISSUER, :8070)
  │ kb_session cookie (UI_SESSION_SECRET): only a server-side session's random secret
  ▼
kb-ui (:8080)   web/ package — FastAPI + HTMX + Jinja2, no BGE-M3
  │ X-API-Key (PIPELINE_API_SECRET)  ╲ QdrantClient (server mode)  ╲ token/feed/admin API
  ▼                                    ▼                              ▼
kb-pipeline (:8000)               pacod-qdrant (:6333)       pacod-id internal (:8071)
  BGE-M3 (or pacod-embeddings, EMBEDDINGS_URL) + embedded OR server Qdrant
  │ Bearer pgw_… (PACOD_GW_API_KEY)
  ▼
pacod-gw (/v1/chat/completions) — every LLM call
```

`pipeline/api.py` **must run with `--workers 1`**: embedded Qdrant holds a RocksDB filesystem lock; the in-memory job store must not be split across processes. In **embedded mode** the Qdrant management section of the UI is hidden; in **server mode** the UI talks directly to Qdrant for collection/snapshot operations, limited to kb's collections (`KB_QDRANT_COLLECTION_PREFIX`, default `kb_`, plus the collections kb's projects own): the Qdrant may be shared on pacod-net.

**UI sign-in & RBAC** (`web/auth.py`, `web/oidc.py`, `web/sessions.py`, `web/identity.py`) — pacod-id only; there are no local accounts. `/kb/login` (also pacod-id's `initiate_login_uri`) starts the authorization-code flow with PKCE S256 (`web/oidc.py`, hand-built: authorize/logout on the public issuer, token/JWKS/internal/admin on `PACOD_ID_INTERNAL_URL`; no discovery, no nonce; the callback checks `state` in constant time and `iss`, RFC 9207). The redirect URIs come from `KB_UI_ORIGIN`, never the request (`/kb/login` first moves to that origin). The callback verifies the access token (`JwtVerifier`: issuer, `aud` `pacod-kb`, a person's `sid`), stores the tokens in a **server-side session** (`ui_sessions` in the UI SQLite file; Fernet under HKDF of `UI_SESSION_SECRET` and the cookie secret; the cookie `kb_session` holds only `{"s": <secret>}`), and clears the cookie first (fixation). Per request `current_principal()` resolves once into `request.state.principal`: row → feed fresh (else `IdentityUnavailable`, 503 page with `Retry-After`) → `sid_revoked`/`is_disabled` (row deleted, sign in again with `ended=1`) → refresh when <30 s left → `role_of(sub)` (none: `NoKbAccess`, 403 page). **Refresh** (`refresh_session`): a per-session `asyncio.Lock` (`app.state.session_locks`), re-read after acquiring, `invalid_grant` = signed out, a network/5xx failure retried once at once (inside pacod-id's 30 s rotation grace), then 503 with the row kept; persisted by compare-and-swap before use. Feed events delete rows (`session.revoked` by sid, `principal.disabled`/`deleted` by sub) because the cache remembers ended sids only 15 minutes; `principal.deleted` (also re-announced from each snapshot until confirmed) additionally calls the pipeline's `/people/{sub}/erase` and, on success, `deletion_done(sub)` (5 attempts, backoff), so pacod-id's tombstone goes. `POST /kb/logout` calls `service.revoke_session(sid)` (revoking the refresh token alone leaves the SSO session live) and redirects to `{issuer}/oidc/logout?client_id&post_logout_redirect_uri`. `/kb/healthz` always answers 200 with `identity: ready|stale|off`. Unsafe methods from a foreign `Origin` get 403. Roles `viewer` < `editor` < `admin` (`web/roles.py`) come from kb's manifest via the feed; `require_write` is the router-level method gate (reads for any role, mutations for editors; `_READ_ONLY_POST_ROUTES` keeps the two search POSTs open to viewers), `require_role("admin")` guards AI Management, prompts, the switches, the gateway test and project deletion. HTMX requests that need sign-in get 401 + `HX-Redirect`. The UI still starts without identity settings (CI does): protected pages then answer 503. Templates get `current_user`, `user_can(role)` and `id_account_url` (pacod-id's account pages) from a context processor that only reads `request.state`. The UI runs **one worker** (locks, feed follower). **UI image**: `Dockerfile.ui` installs only the `ui` dependency group from `uv.lock` (no docling/torch; `pacod-id` from `vendor/wheels`), runs as uid 10001 (entrypoint `docker/ui/entrypoint.py` fixes old root-owned volumes, then drops privileges), health check `/kb/healthz`, and serves the vendored `web/static/htmx.min.js` (htmx 1.9.12).

### Pipeline flow

```
Source (file / URL)
  → pipeline/acquisition.py: ingest_document()
      SHA-256 dedup · parse · legal promotion · write document.md + manifest.json + source snapshot
  → pipeline/indexer.py: index_document()
      chunk_document() · BGE-M3 embed · upsert to Qdrant (vector) + SQLite FTS5 (keyword)
  → pipeline/retrieval.py: search()
      hybrid RRF fusion (k=60) over vector rank + keyword rank · valid_until/as_of filtered in
      both searches · optional cross-encoder rerank of the fused head (pipeline/reranker.py)
```

### Storage layout (`KB_ROOT/`)

| Path | Contents |
|---|---|
| `documents/<id>_<slug>/document.md` | Canonical Markdown (YAML front matter + body) |
| `documents/<id>_<slug>/manifest.json` | Acquisition metadata + lifecycle events |
| `documents/<id>_<slug>/source.*` | Raw source snapshot |
| `index/qdrant/` | Embedded Qdrant vector store |
| `index/fts5.db` | SQLite FTS5 keyword store |
| `watch.json` | URLs to poll in watch mode |
| `dropzone/` | Drop files here for automatic ingestion (overridable via `KB_DROPZONE`) |
| `done/` | Successfully ingested or already-known dropzone files (overridable via `KB_DONE`) |

### Key design decisions

**Versioning** — superseding a document sets `valid_until` (ISO date) on four locations simultaneously: `document.md` front matter, `manifest.json`, FTS5 `chunks_meta`, and Qdrant point payloads. `search()` filters by `valid_until IS NULL` by default; pass `as_of=` or `include_historical=True` to relax this. Admin deletion (`delete_document()` / `DELETE /documents/{doc_id}`) is also available and wipes Qdrant points, FTS5 records, and the archive folder permanently — use supersession for normal version management, deletion only for purging mistakes.

**Chunk IDs** — stable string: `{doc_id[:16]}#{path_slug}#{seq_within_section}` (16 hex chars; 8 collided at ~1 % per 10k documents, overwriting another document's FTS row and Qdrant point — changing this requires `kb rebuild --all-projects`). Qdrant uses a deterministic UUID derived from this string (MD5). IDs are not sequential integers — they encode heading structure.

**Byte offsets** — `byte_start`/`byte_end` are UTF-8 byte offsets into the stripped body (front matter removed). This matters for Cyrillic content where char and byte positions diverge.

**Embedded text** — each chunk's `embedded_text` prepends a `[DocTitle > H1 > H2]` breadcrumb before going to the embedder. Table chunks additionally prepend the nearest preceding paragraph as caption context. The stored `embedded_text` is this augmented form, not the raw chunk text.

**Qdrant null filter** — current-only queries use `IsNullCondition` on `valid_until`. Qdrant treats missing payload keys and explicit `null` identically here, so there is no need to set a sentinel value.

**Language validation** (`pipeline/acquisition.py`) — after parsing, the detected language is checked against `SUPPORTED_LANGUAGES = {"en","de","bg","ru","sr","mk","hr","sl","unknown"}`. Unsupported languages raise `ValueError` before any files are written. `"unknown"` is accepted with a warning.

**Browser fetch** (`pipeline/parsers/web.py:_browser_fetch`) — all URL fetches use httpx with a Chrome 131 `User-Agent` plus the full set of headers a real browser sends on cold navigation (`Accept`, `Accept-Language`, `Sec-Fetch-Dest/Mode/Site/User`, `Upgrade-Insecure-Requests`, `Cache-Control`). This avoids rejection by sites that check headers beyond just the UA. All fetches go through `_http_get`: redirects are followed manually (max 5) and every hop must be `http(s)` (`require_http_url`); responses stream with a size cap (`WEB_FETCH_MAX_BYTES`, default 50 MB) and a 180 s overall deadline. `WEB_FETCH_ALLOW_PRIVATE=false` additionally rejects hosts resolving to loopback/private/link-local addresses (SSRF guard; default `true` for local deployments). SSL errors are detected by walking the httpx exception chain for `ssl.SSLError` (httpx surfaces them as `ConnectError`) and retried with `verify=False` only while `ALLOW_INSECURE_TLS` is true (default; logged). `Accept-Encoding` omits `br` (no brotli decoder installed). Do **not** revert to `trafilatura.fetch_url()` — it sends the trafilatura bot UA.

**URL ingest never reads local files** — `IngestUrlRequest` validates `http(s)` and every URL ingest path calls `ingest_document(..., url_only=True)`; only upload, dropzone, CLI and job replay pass local paths. `/watch` `watch_file` must lie inside `KB_ROOT`.

**Angular SPA fetch** (`pipeline/parsers/web.py:_fetch_apis_bg`) — sites such as `*.apis.bg` are Angular SPAs that return an empty `<app-root>` shell to trafilatura. `_fetch_apis_bg` matches `https://<subdomain>.apis.bg/doc/<id>` URLs, calls the hidden REST backend at `web-api.apis.bg` (`DocInfo` + `DocTextJson` endpoints), and converts the returned HTML paragraph list to Markdown. Uses `Accept-Encoding: gzip, deflate` (no `br`) to avoid requiring the optional `brotli` package for httpx. Called from **both** `WebParser.parse()` (when the URL is passed directly) **and** `_parse_bytes()` (when `acquisition.py` fetches bytes first and calls `_parse_bytes` directly), so the handler is always tried before trafilatura regardless of the call path. Returns `None` on any error and falls back to the normal trafilatura path.

**Keyword queries** (`pipeline/indexer.py`, `pipeline/text_lexicon.py`) — `KEYWORD_QUERY_MODE` picks how a query becomes a keyword search; the indexes (FTS5 `unicode61`, PostgreSQL `simple`) are unchanged by all modes. `legacy` (default): `_sanitize_fts5` quotes every word and FTS5 ANDs them, so natural questions ("What does …") usually match nothing. `or`: `analyze_query()` drops stopwords (Latin/Cyrillic lists), keeps numbers, acronyms and short tokens exact, turns other words into prefixes after stripping one inflection ending (≥ 4 letters stay: законите → закон*, personenbezogener → personenbezogen*), and makes "marker + number" a phrase ("чл 17", "article 17"); any term may match, BM25 ranks. `and_or`: chunks matching every term first, then the OR matches. PostgreSQL's analysed search orders by the number of matched terms, then `ts_rank_cd(…, 1)` (it has no IDF), under `SET LOCAL statement_timeout` (`KEYWORD_PG_TIMEOUT_MS`; a timeout leaves the query vector-only). `RRF_KEYWORD_WEIGHT` weights the keyword list in fusion. Switch modes only on eval evidence (docs/retrieval-eval.md).

**Reranking and scores** (`pipeline/reranker.py`, `pipeline/retrieval.py`) — with a reranker, each leg fetches `RETRIEVAL_CANDIDATE_K`, the first `RERANK_TOP_N` fused candidates are scored by a sentence-transformers `CrossEncoder` (sigmoid, [0, 1]; identical texts scored once), or with `RERANKER_URL` by the shared embeddings service's `/rerank` (`RemoteReranker`: bge-reranker-v2-m3, sigmoid scores, one attempt within `RERANKER_TIMEOUT_MS`, nothing loaded locally), and re-sorted; any error or a busy gate (`RERANK_GATE_TIMEOUT_MS`) keeps the fused order. Without one, the candidate depth stays `max(top_k*3, 20)` — deeper lists change RRF's order. `RerankerHolder` loads the model in a daemon thread at startup when `RERANKER_ENABLED`, or when switched on via `POST /settings {"reranker_enabled": true}` (the only way to retry a failed load). A request's `rerank` only selects an already loaded reranker: a request never loads one (GBs of RAM). Every returned result is reranked, so latency grows with `max(top_k, RERANK_TOP_N)`. `/health` and `GET /settings` report its state. `SearchResult.score` is the ordering score (`rerank_score` when reranked, else `rrf_score`); `/query` adds `reranked` and `score_kind`, and `min_score` filters only reranked results.

**Inference scheduling** (`pipeline/inference.py`) — every model call (embedder, reranker) passes one `InferenceGate`: torch uses all cores per call, so concurrent calls only slow each other. `BgeM3Embedder.encode` (ingest) embeds length-sorted micro-batches of at most `EMBED_BATCH_TOKENS` padded tokens under `GATE.batch()`; `encode_query` (search) takes `GATE.interactive()` and so overtakes waiting batches — a query waits for at most one micro-batch — and is LRU-cached (`QUERY_EMBED_CACHE_SIZE`). `count_tokens` uses a private tokenizer copy, off the gate. **Remote embeddings**: with `EMBEDDINGS_URL` set, `make_embedder` returns a `RemoteEmbedder` instead (POST `{EMBEDDINGS_URL}/embed` `{"texts": [...]}` → `{"embeddings": [[...]]}`, pacod-ap's service: the same BGE-M3 dense normalized vectors) — tokenizer only (`AutoTokenizer`, no weights), the same token-budget micro-batches (`_micro_batches`) and LRU query cache, no gate; connection errors/timeouts/5xx retried with backoff (`EMBEDDINGS_TIMEOUT_SECS`), 4xx and a vector that is not `VECTOR_DIM` (1024, the collections' size) raise `EmbeddingServiceError`. `PipelineEmbedder` (= `BgeM3Embedder | RemoteEmbedder`) is the annotated type in the API. `configure_threads(TORCH_NUM_THREADS)` runs before models load: 0 derives the count from CPU affinity and the cgroup quota on Linux (torch would count the host's cores), keeps torch's default elsewhere, and exports `DOCLING_NUM_THREADS` to match (docling otherwise resets torch to 4 threads on its first PDF).

**Job queue** (`pipeline/api.py`) — job runners go through `_enqueue()` onto one dedicated worker (`_job_executor()`, a single-thread `ThreadPoolExecutor`), not Starlette's `BackgroundTasks` (which share the threadpool serving `/query`); jobs run FIFO and stay `pending` until they start. `_job_slot` waits up to `JOB_LOCK_TIMEOUT_SECS` for the mutation lock (dropzone scan, project switch) before failing the job. Tests run runners inline (autouse `_inline_job_queue` in `tests/conftest.py`); patch `api._job_executor` to capture submissions.

**Embedding reuse** (`pipeline/indexer.py:_reusable_vectors`, `pipeline/vectorstore.py`) — before embedding, `index_document` looks up vectors for chunks whose `reuse_key(content_hash, embedded_text)` matches a stored point of the same `embedding_model` (payload tag; untagged points only with `EMBED_REUSE_UNTAGGED`) via `fetch_reusable_vectors` (scroll with `MatchAny` on `content_hash`), or in the `vector_cache` a rebuild passes (`snapshot_vectors()` taken before `drop_all()`, capped by `REBUILD_REUSE_MAX_POINTS`). Lookup errors embed everything. A superseding version therefore embeds only its changed chunks.

**OCR** (`pipeline/ocr.py`, `OCR_ENABLED=true`) — `analyze_pdf()` converts once without OCR (cached converters per engine) and classifies pages by their per-page Markdown (`export_to_markdown(page_no=)`); with no image-only page its body is used directly. `dual_extract()` OCRs with docling's default engine and, when the `tesseract` CLI exists, with tesseract, comparing page by page; one engine gives `OCR_SINGLE_ENGINE_CONFIDENCE`. The OCR path runs under `_CONVERT_LOCK` with the PDF page/size limits. `DOCLING_TABLE_MODE=fast` switches TableFormer to its fast mode (`apply_table_mode`).

**JSON ingestion** (`pipeline/parsers/json_parser.py`) — `.json` files are parsed into heading-aware Markdown rather than dumped verbatim: mapping keys become headings (nested) or `**key:** value` lines (scalars), scalar arrays become bullet lists, and arrays of objects use each item's `name`/`title`/`id` as the heading (falling back to `Item N`) so the `[DocTitle > H1 > H2]` search breadcrumb stays meaningful. The title is taken from a top-level `title`/`name`/`heading`/`id` field, else the filename stem. Invalid JSON raises `ValueError` (dropzone routes it to `KB_FAILED`). Supported extensions are listed in `parsers/__init__.py:SUPPORTED_EXTENSIONS`.

**Content security** (`pipeline/content_security.py`) — defends against indirect prompt injection and spam in ingested documents (their text becomes `embedded_text` returned by `/query` straight into a downstream LLM). `scan_content()` runs inside `ingest_document()` on the **deterministic parse, before LLM conversion** (the converter could act on injected instructions, and conversion strips zero-width/bidi/hidden-markup signals), and again on the converted body if conversion ran; quarantined content is never sent to the converter. It normalizes a *copy* of the text (NFKC, lowercase, whitespace-collapse; plus de-spaced copies of letter-spaced runs such as `i g n o r e` to defeat letter-spacing) and applies rule tables: multilingual injection phrases (EN + DE/RU/BG), bidi-override/zero-width obfuscation, base64/hex blobs (decoded and re-scanned), hidden HTML/markup, and spam heuristics (link density; verbatim repeated lines as a share of the document; vocabulary diversity averaged over 100-word segments — a whole-document ratio falls with length and used to quarantine every long law). Each injection rule carries its own severity: only unambiguous instruction overrides (EN/DE/RU/BG "ignore previous instructions") are high; role reassignment to an AI, prompt reveal, DAN and system-prompt override are medium; developer mode and exfiltration phrasing are low — ordinary technical prose ("enable developer mode", "post data", "jailbreak") must not block (see the false-positive corpus in `tests/test_content_security.py`). Scoring is **tiered**: a single high-severity injection/obfuscation finding (or threat-score ≥ block threshold) → **block** (`ValueError`, which the dropzone routes to `KB_FAILED`, like the language gate); spam never blocks on its own. Medium-confidence → **quarantine**: the document is still written for audit but its manifest `status` is set to `"review"` (reusing the existing enum — no schema change) with a `security_flagged` event, and `index_document()` refuses to index anything whose status isn't `"ok"`, so flagged content never reaches Qdrant/FTS5 or search. An optional LLM second opinion through the AI gateway (`CONTENT_SECURITY_LLM_ENABLED`, off by default; model `CONTENT_SECURITY_LLM_MODEL` or the runtime `security_model`; JSON-schema answer, `CONTENT_SECURITY_LLM_TIMEOUT_SECS` = 15) is consulted only for non-blocking verdicts (on a head/middle/tail sample of long documents) and **fails open** on any error. `ingest_document(..., trusted=True)` (CLI `--trusted`, API `/ingest/file` form field) bypasses the scan for legitimate security-research content. Output side: `/query` wraps each `embedded_text` via `wrap_untrusted()` (delimited untrusted-data fence, gated by `CONTENT_SECURITY_WRAP_OUTPUT`). Env flags live in `pipeline/config.py` (`CONTENT_SECURITY_ENABLED`, `CONTENT_SECURITY_WRAP_OUTPUT`, `CONTENT_SECURITY_LLM_ENABLED`, `CONTENT_SECURITY_LLM_MODEL`, `CONTENT_SECURITY_BLOCK_THRESHOLD`, `CONTENT_SECURITY_QUARANTINE_THRESHOLD`).

**Runtime settings** (`pipeline/api.py:_runtime`) — a module-level `dict[str, Any]` initialised from config at lifespan start and mutable at runtime via `GET /settings` (read) and `POST /settings` (update). Changes are **not persisted** across restarts; env vars remain authoritative. `GET /settings` also reports `gateway_configured`. The keys:
- `content_security_enabled` (bool) — toggles the content-security scan without a restart. Every API-side ingest path — single URL, URL batch, upload, the dropzone watcher, `/dropzone/scan` and `/watch` — takes its switches from `_ingest_options()` (an `IngestOptions` from `pipeline/acquisition.py`), which reads this key and `llm_converter_enabled`; the CLI follows the env config instead. The dashboard **Security scan ON/OFF** button calls `POST /kb/pipeline/settings/security`, which POSTs `{"content_security_enabled": value}` and swaps the toggle widget in place via HTMX `outerHTML`.
- `llm_converter_enabled` (bool) — toggles LLM-based document conversion without a restart. The dashboard **AI converter ON/OFF** button calls `POST /kb/pipeline/settings/converter`, which POSTs `{"llm_converter_enabled": value}` and swaps the toggle widget (admin-only: it spends money; the widget says when the gateway is not set up). Per-ingest override is also available via the ingest form's conversion mode field (`auto`/`true`/`false`; `yes`/`no` are accepted, anything else is a 422).
- `active_collection` (str) — the current Qdrant collection name. POSTing `{"active_collection": "name"}` replaces `app.state.vector_store` with a `QdrantVectorStore` for an **existing** collection (404 for unknown names — no auto-create on typos). Project and collection switches hold the mutation lock and are refused with 409 while any job is queued or running; ingest jobs capture their project when queued. Selecting a collection that a project owns selects that project (`_collection_owner`), so vectors and keyword rows stay paired; a collection no project owns can be selected for vector-only search, and every write route (ingest, upload, reindex, watch, dropzone scan) answers 409 until a project is selected (`_require_write_target`; the dropzone watcher skips its scans). `/query` scopes keyword hits to the owner of the searched collection. The dashboard **collection selector** dropdown calls `POST /kb/pipeline/settings/collection`; `GET /collections` lists all Qdrant collections with point counts for the dropdown.

**Legal promotion** (`pipeline/promote_legal.py`) — runs when `doc_type` is one of `legal_code`, `regulation`, or `directive`. Promotes bare lines matching patterns for 8 languages (EN, DE, BG, RU, SR, MK, HR, SL) to Markdown headings before chunking. Supported `doc_type` values: **Legal** — `legal_code`, `regulation`, `directive`, `decision`, `circular`; **Content** — `article`, `paper`, `report`, `document`, `guide`; **General** — `generic`, `web_page`. Only the three legal types trigger legal heading promotion; see below for `paper` and `article` handling.

**Paper heading promotion** (`pipeline/promote_paper.py`) — runs when `doc_type == "paper"`. Promotes bare section-header lines (Abstract, Introduction, Methods, Results, Discussion, Conclusion, References, etc.) to Markdown `##` headings, improving chunk breadcrumbs and retrieval quality for academic papers ingested from PDF or HTML. Supports EN, DE, and BG/RU. Matching is case-insensitive; an optional trailing colon is ignored; multi-word headers (e.g. "Materials and Methods") are matched in full.

**Article metadata extraction** (`pipeline/promote_article.py`) — runs when `doc_type == "article"` and the source is a URL. Calls `trafilatura.bare_extraction()` on the already-fetched HTML bytes (no extra network call) to extract author, publication date, and outlet name. These are stored in the manifest as optional fields `meta_author`, `meta_published_date`, and `meta_publication_venue` (all nullable strings). Fails open — any extraction error silently produces `null` values. Both `frontmatter.json` and `manifest.json` schemas declare these optional properties.

**Content noise filter** (`pipeline/content_filter.py`) — `strip_noise(body: str) -> str` runs in `ingest_document()` right after parsing and before any type-specific heading promotion, for all doc_types. Splits the body on double newlines and filters out paragraphs that are structural noise: isolated page numbers (1–4 digits with optional decorators), running headers/footers (short identical text appearing ≥ 3 times), known boilerplate phrases matched in full (cookie notices, JS warnings, social-share prompts, newsletter sign-ups, "continue reading", "powered by", etc. — only for paragraphs ≤ 200 chars), and pure link-navigation blocks (≥ 3 Markdown links with ≥ 80% link density). Headings (`#`) and table blocks (≥ 3 `|` characters) are always kept. Long paragraphs (> 200 chars) are only checked for link-nav density, never for boilerplate phrases. Gated by `CONTENT_NOISE_FILTER_ENABLED` env var (default `true`; config field `content_noise_filter_enabled`). Fenced code blocks are copied verbatim and image galleries (`![..](..)`) are not counted as navigation links. trafilatura's `favor_recall=True` is intentionally permissive and leaves this noise behind; the filter cleans it up before chunking.

**AI gateway** (`pipeline/gateway.py`) — every LLM call goes through pacod-gw: one sync httpx client (`Gateway`, process-wide via `get_gateway(config)`, on `app.state.gateway`) speaking the OpenAI chat-completions shape to `POST {PACOD_GW_URL}/v1/chat/completions` with a `pgw_` key (`PACOD_GW_API_KEY`). kb holds no provider keys and no price tables: the gateway routes by model name (`provider/model` or a pool `@name`), translates a PDF `file` part for models that read documents, fails over, and prices each call. Attribution headers carry opaque ids only (`x-gw-task`, `x-gw-trace` = job or document, `x-gw-end-user` = project, `x-gw-user-id`). One retry, only for 429 after `Retry-After` (≤30 s); never for 402/504. `finish_reason` `length`/`content_filter`, a refusal, or empty text raise `GatewayOutputError`; errors name status, gateway error code and request id, never the body. Streaming uses `stream_options.include_usage` (the final chunk carries `usage.cost`); the httpx read timeout is the idle timeout (`PACOD_GW_IDLE_TIMEOUT_SECS`, 120) and a monotonic deadline caps the total. `configured()` false (URL or key blank) means AI is off: conversion is skipped with one log line and the content-security second opinion does not run. Tests use `httpx.MockTransport` (`tests/test_gateway.py`) or a fake gateway passed as `gateway=`.

**LLM-based document conversion** (`pipeline/parsers/llm.py`) — optional second pass in `ingest_document()` after the language check, before the noise filter and heading promotions. `convert_with_llm(result, config, *, source_bytes, source_ext, runtime_config, session_factory, attribution, gateway)` streams the document through the gateway: a PDF of at most `gateway.MAX_PDF_BYTES` (20 MiB raw; base64 stays under gw's 32 MiB body limit) as a file part, else the extracted text (capped at `_MAX_INPUT_CHARS`); a model without documents (`unsupported_feature`) gets the text instead. It returns a `ParseResult` with `extraction_method="vlm"`, `converter` = the model served, and `llm_usage` carrying tokens plus the gateway's cost, currency and request id. **`ingest_document` catches any conversion failure and keeps the deterministic parse.** A conversion under 25 % of a ≥2,000-char body is logged (never rejected). Settings: `LLM_CONVERTER_MODEL` (default `anthropic/claude-opus-5-5`; a bare legacy name is qualified, using `LLM_CONVERTER_PROVIDER` when set), `LLM_CONVERTER_MAX_TOKENS` (64000), `LLM_CONVERTER_TEMPERATURE` (blank = none sent), `LLM_CONVERTER_TIMEOUT_SECS` (1800), overridable at runtime (`pipeline/runtime_config.py`: `converter_model`, `converter_max_tokens`, `converter_temperature[_enabled]`, `security_model`; the old `llm.primary_*` keys are read as fallbacks). Usage rows (`usage_events`, `ai_interactions`) record the gateway's `cost_usd`/`currency`/`request_id` with `cost_source` `gateway` or `unpriced`; kb no longer estimates cost. Legacy variables (`ANTHROPIC_API_KEY`, `LLM_CONVERTER_API_KEY`, `LLM_CONVERTER_BASE_URL`, `SECRETS_KEY`, `TABLE_RECONSTRUCTION_MODEL`, …) are ignored with one warning at start (`config.warn_legacy_env`).

**UI CSS design system** (`web/static/style.css`) — templates use a custom class vocabulary built on top of Bootstrap 5: `.section-card` (card with `.sc-header`/`.sc-body`), `.config-row` (horizontal label+control pair with `border-top` dividers between adjacent rows), `.config-label`/`.config-hint` (label + muted description), `.action-list` (vertical button list), `.stat-card` (clickable count card with `.s-total`/`.s-active`/`.s-muted`/`.s-danger` modifiers), `.opts-group`/`.opts-header` (bordered option group), `.fmt-badge` (monospace format chip), `.nav-section` (sidebar section label). Critical: `.sidebar .nav-section` needs `display: block` because `<span>` is inline by default. The dashboard Configuration section includes the three toggle partials via `{% include %}` directly inside `.section-card` without a `.sc-body` wrapper so that `config-row + config-row { border-top }` CSS produces dividers; each partial must therefore be the `.config-row` root itself (not wrapped in an extra div).

**Selective sources export** (`pipeline/api.py:GET /export/sources`, `web/routers/pipeline.py`) — `GET /export/sources` and `/export/sources/csv` accept an optional list of `doc_ids` as repeated query parameters (e.g. `?doc_ids=abc&doc_ids=def`). When present, only those rows are included in the export; when absent, all documents are exported. The web UI Documents page builds the URL via JavaScript `url.searchParams.append('doc_ids', id)` for each checked checkbox, so the button label shows "(N selected)" vs "(all)". FastAPI requires `Query(default=[])` for list-typed query params — a plain default `[]` is not picked up.

**Qdrant point browser** (`web/routers/qdrant.py:browse_points`) — supports filtering to a single document via `doc_id: str = ""`. When set, a `FieldCondition(key="source_id", match=MatchValue(value=doc_id))` is added to the Qdrant filter (same field as used by bulk delete). The conditions list is typed `list[Any]` — using a union like `list[FieldCondition | IsNullCondition]` triggers mypy invariance errors because qdrant-client's own type annotations use a wider union (`list[FieldCondition | IsEmptyCondition | IsNullCondition | ...]`) and Python list is invariant. Source_id cells in the table are HTMX links that re-submit the browse form filtered to that doc, letting users click into a document's points without knowing/typing the full 64-char SHA-256. A `<datalist>` populated from the current page's source_ids provides autocomplete in the text input.

**Qdrant browse page size** (`web/routers/qdrant.py:browse_points`) — `page_size: str` param validated against `_VALID_PAGE_SIZES = {"50","100","1000","2000","5000","all"}`. When `page_size == "all"`, the route scrolls in batches of 1000 up to 10 000 points (`_MAX_BROWSE_ALL`); beyond that a "Next →" link continues from the cursor. For all other sizes the normal cursor-pagination path is used. Page size is threaded through the "Next →" pagination link so it is preserved across pages.

**Qdrant point export** (`web/routers/qdrant.py:export_points`) — `GET /{collection}/export` accepts either `point_ids: list[str]` (fetch specific UUIDs via `client.retrieve()`) or `doc_id: str` (scroll all matching points via filter loop). Exactly one must be non-empty. Returns `application/json` with `Content-Disposition: attachment` named `qdrant_{collection}_{doc_id[:8]|"selected"}_{ts}.json`. The JS `exportPoints()` function builds the URL with repeated `point_ids` params from checked checkboxes; the "Export all for this document" link appends `?doc_id=…` directly.

**Dropzone auto-ingest** (`pipeline/dropzone.py`) — the pipeline API starts a daemon thread on startup that polls `KB_DROPZONE` every `DROPZONE_INTERVAL_SECS` seconds (default 10; 0 to disable). For each stable, non-hidden file (mtime > 2 s old) it computes SHA-256, checks against existing manifests, and either ingests+indexes the file, indexes a known document that has no chunks yet, or logs "already known". New documents are tagged with the active project and indexed into its collection (the thread re-reads `app.state.vector_store` on every scan). Processed files move to `KB_DONE`, failures to `KB_FAILED`. Each scan that touches at least one file creates a `dropzone_scan` job visible in the Jobs view. The watcher acquires the mutation lock non-blocking so it never races with a concurrent rebuild or reindex. Uploaded files via the web UI preserve the original filename in the manifest (no random temp names).

**Document store** (`pipeline/document_store.py`) — optional relational database backend for ingested documents. `DocumentStore` is a base class (not `typing.Protocol`, so `isinstance()` checks work) with two concrete implementations: `FilesystemDocumentStore` (default; thin delegation to existing file ops) and `DatabaseDocumentStore` (SQLAlchemy 2.0 synchronous sessions — NOT async, because pipeline code runs in background threads; `_session_scope()` context manager handles commit/rollback). `make_document_store(config)` is the factory; `_build_database_url(config)` assembles `postgresql+psycopg2://user:password@host:port/name` (`load_config()` refuses database mode without PostgreSQL settings; tests construct `DatabaseDocumentStore` on SQLite engines directly). Optional manifest fields without a column (`meta_*`) live in the JSON `kb_documents.extra` column; bounded string columns are truncated on save; missing documents raise `KeyError` like the filesystem store; listings defer `body`/`source_bytes` and load events in one query. Credentials are URL-encoded via `urllib.parse.quote(…, safe="")`. All pipeline functions (`ingest_document`, `index_document`, `supersede_document`, `delete_document`, `rebuild_index`, dropzone and watch loops) accept an optional `store: DocumentStore | None = None`; when `None` (the default), every existing filesystem code path is completely unchanged. In database mode `ingest_document` returns `(doc_id, None)` — no `documents/` folder is created; `index_document` receives `doc_data=(manifest_dict, body)` in place of a path; `chunk_count` is updated by the caller via `store.update_manifest(doc_id, chunk_count=len(chunks))` after indexing. ORM models live in `pipeline/db_models.py` (`KbDocument` + `KbDocumentEvent` with `ON DELETE CASCADE`); `Integer` (not `BigInteger`) is required for `KbDocumentEvent.id` PK because SQLite autoincrement requires the plain `INTEGER` affinity. Tables are created on first startup via `Base.metadata.create_all(engine)`. The optional `postgres` extra (`uv sync --extra postgres`) installs `psycopg2-binary`; `sqlalchemy>=2.0` is always a core dependency.

**The ledger** (`pipeline/ledger.py`) — runtime settings (`app_settings`), prompt overrides, `usage_events` and `ai_interactions` exist in both backends: the document database in database mode, `{index_dir}/ledger.db` (SQLite, WAL) in filesystem mode. `ledger_session_factory(config, store)` returns it; routes read `app.state.ledger_factory` via `_ledger_factory_from_app`. Saving with no ledger raises instead of reporting success. Late columns are back-filled by `ensure_ledger_columns`. Usage buckets group by a `substr` of the ISO `occurred_at` (no SQLite-only `strftime`); weeks are ISO weeks.

**Backend parity** — watch/dropzone/rebuild/update paths are expected to produce the same externally visible behavior in both backends: URL dedup uses the active store; rebuild updates real `chunk_count`; exports include lifecycle `events` in both backends. The web router must not read `KB_ROOT/documents` directly.

**Projects** (`pipeline/projects.py`) — projects are **fully isolated** document collections, each backed by its own Qdrant collection. The registry has two backends chosen by `make_project_registry(config, session_factory)`, mirroring the document store: `ProjectRegistry` (filesystem JSON at `KB_ROOT/projects.json`) and `DatabaseProjectRegistry` (the `kb_projects` table — the single source of truth in database mode). Both implement the shared `ProjectStore` interface (`list`/`get`/`create`/`delete`/`update_collection_name`/`ensure_default`). Isolation is enforced end-to-end: (1) each document carries a `project` slug — `KbDocument.project` (nullable; `DatabaseDocumentStore` persists it on `save`, returns it in `_to_dict`/`list_all`/`load_manifest`, and a startup `ALTER TABLE … ADD COLUMN project` back-fills pre-existing databases); (2) `GET /documents` filters by the active project slug; (3) vector search is scoped to the active project's Qdrant collection via `_switch_active_project`; (4) FTS is scoped by the `project` column (`FtsDb`/`PostgresFtsDb`). Creating a project auto-creates its Qdrant collection and rejects a `collection_name` already assigned to another project. `POST /settings {"active_project": slug}` atomically swaps `app.state.vector_store` to the project's collection (refused with 409 while a job is queued or running). **Tagging**: `ingest_document(project=None)` resolves the registry's default project (`default_project_slug`); dropzone, watch and CLI ingests pass the active project. Older versions stamped the literal `"default"`; `retag_legacy_default_project()` runs at API startup and moves `"default"`/untagged documents (manifests, `document.md`, FTS rows, Qdrant payloads) to the real default slug — idempotent, skipped when a project is actually named `default`. **Rebuild** is per project: `rebuild_index(..., project=, default_project=)` drops only that project's collection and FTS rows; `rebuild_all_projects()` / `POST /rebuild?all_projects=true` / `kb rebuild --all-projects` rebuild every project into its own collection; an unscoped API rebuild is refused. Deleting a project drops its FTS rows, its Qdrant collection, and all of its document rows/folders. On first database-mode startup a legacy `KB_ROOT/projects.json` is migrated into `kb_projects` once (idempotent) via `DatabaseProjectRegistry.import_from_json`.

**Export** (`GET /export` API, `GET /kb/pipeline/export` web proxy, `kb export` CLI) — dumps all ingested document metadata and Markdown bodies to a single JSON file. Each entry in the `documents` array contains all manifest fields plus `body` (canonical Markdown) and `events` (lifecycle log); `source_bytes` (binary blob) is excluded. The pipeline API returns it as a file attachment (`Content-Disposition: attachment; filename="kb_export_<timestamp>.json"`); the web UI has an **Export JSON** button in the Documents list that proxies the download; the CLI writes to `--output FILE` or stdout when omitted.

### Testing

Tests use `tmp_path`-based `kb_root` and `config` fixtures (see `tests/conftest.py`). `conftest.py` also points `PIPELINE_API_URL` at a closed local port: the default `kb-pipeline` host costs a ~5 s DNS timeout per UI request (the full suite runs in ~20 s instead of minutes). `GIT_AUTOCOMMIT=false` is always set in tests. The UI's tests sign in through the real flow against a fake pacod-id (`tests/fake_id.py`, behind `httpx.MockTransport` as `app.state.id_transport`): `tests/web_support.py` has `web_client(fake)` and `login_as(client, fake, role)`; `conftest.py` sets the `PACOD_ID_*` test values, with a closed port as the internal URL when no fake is installed. DOCX and PDF fixtures are created programmatically via `python-docx` / `fpdf2` (both dev-only deps). Tests do not hit the network or load BGE-M3; use the real embedder only for `eval/run_eval.py --min-recall`.

### JSON schemas

`pipeline/schemas/` holds `chunk.json`, `frontmatter.json`, and `manifest.json`. Every chunk and manifest is validated against these schemas before being written; failures raise `jsonschema.ValidationError`.
